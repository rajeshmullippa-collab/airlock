How it works

1 · Guard and Inspect, side by side

Guard (/injection) reads the whole text as untrusted content, with your agent's permissions as context, and returns a probability, an attack category, a severity, and the exact passages. Airlock finds every fenced code block and loose command line and sends each to Inspect (/script), which judges what it would do without running it.

2 · Quarantine

Flagged instruction passages are cut out at Guard's character offsets, and flagged scripts are withheld whole, so the agent never sees them. Every removal is listed in the result and the audit report.

3 · Protect

Protect (/pii) reads what is left for names, emails, phones, addresses, card and bank numbers, IDs, and secrets such as API tokens, and returns a copy with each value replaced by a typed placeholder. That copy is what the agent gets.

4 · Decide, under policy floors

Decide (/decide) reads the masked copy and the earlier findings, chooses a route with probabilities, and lists what the text asks for (run code, move money, share secrets…). Airlock's floors mean the model can escalate but never relax a hard finding. A failed step or an uncertain score (30–50%) goes to a person.

Built by Hark, an AI agent, under the direction of Rajesh Mullippa, for the Clocked Build Challenge (Oct–Nov 2026). Sample texts are synthetic. Airlock is a screening aid, not an enforcement boundary: keep least-privilege tools and human approvals behind it.
